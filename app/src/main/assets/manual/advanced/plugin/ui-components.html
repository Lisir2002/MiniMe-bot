页面样式、组件与事件

插件页面可使用宿主主题、Vue 组件库和文件订阅，使界面与 App 保持一致，并在数据变化时刷新。

主题

在页面 HTML 壳中引用主题和组件样式；Vue 与桥脚本的统一引入方式见页面构建：

<link rel="stylesheet" href="/__minibot/theme.css">
<link rel="stylesheet" href="/__minibot/ui.css">

可用 CSS 变量：

变量 用途
--minibot-bg 页面背景
--minibot-surface 卡片、输入框表面
--minibot-on-surface 正文文字
--minibot-primary 主色
--minibot-error 错误色
--minibot-success 成功色
--minibot-warning 警告色
--minibot-radius-* 圆角
--minibot-space-* 间距
--minibot-font-scale 字号缩放

深浅色切换时，宿主直接更新变量，页面不会重新加载；请依赖 CSS 变量，不要在脚本中缓存具体颜色值。minibot.applyTheme(variables) 可临时覆盖变量，并派发 minibot:theme 事件。

布局

内容区需要居中并限制最大宽度时，应同时设置 box-sizing: border-box; width: 100%; max-width: 860px; margin: 0 auto;，使其从首次显示起即占满可用宽度。若仅设置最大宽度和自动外边距，在纵向 Flex 布局中会按内容收窄，待异步数据返回后才撑开。

.page {
  box-sizing: border-box;
  width: 100%;
  max-width: 860px;
  margin: 0 auto;
  padding: 16px;
}

Vue 组件库

按 Vue 入口注册 MiniBotUI 后，在单文件组件中使用 minibot-*：

<template>
  <minibot-field label="描述">
    <minibot-textarea v-model="description" placeholder="输入描述" />
  </minibot-field>
</template>

<script setup lang="ts">
import { ref } from 'vue';

const description = ref('');
</script>

组件名与 props 的类型提示见页面类型提示。

输入框

minibot-input、minibot-textarea 的外观与 App 输入框一致，包括圆角、描边、文字间距、深浅色、聚焦和禁用状态。

  • 每个 minibot-field 放置一个输入组件；
  • 空值且未聚焦时，标签显示在框内；聚焦或有内容时标签浮到边框处，提示文字在标签浮起后显示；
  • 点击标签也可聚焦输入框；
  • disabled 时底色保持不变，文字与边框变淡；
  • type="password" 时默认隐藏内容，右侧自动显示明文/隐藏切换按钮；切换仅改变显示方式，保留原内容和光标位置；禁用时切换按钮同样禁用。

对话框

minibot-dialog 对齐 App 的居中对话框：标题、内容和底部文字按钮分区排列，取消在左、确认在右。

文字确认：

<minibot-dialog v-model="confirmOpen" title="确认操作"
  message="确定继续执行吗？" @confirm="runAction"></minibot-dialog>

输入表单：

<minibot-dialog v-model="editOpen" title="修改名称" confirm-text="保存"
  :confirm-disabled="!name.trim()" @confirm="saveName">
  <minibot-field label="名称">
    <minibot-input v-model="name" placeholder="输入名称"></minibot-input>
  </minibot-field>
</minibot-dialog>
  • 文字确认通过 message 显示说明；
  • 输入弹窗将输入组件放入默认插槽，输入框底色透出弹窗颜色；
  • 内容过长时仅滚动内容区，底部按钮保持可见；
  • confirm-disabled 为 true 时不可确认；
  • 确认将触发 confirm 并关闭；取消按钮、遮罩、返回键或 Escape 将触发 cancel 并关闭；
  • 输入值由页面的 v-model 管理，取消时是否恢复原值由页面决定。

minibot-bottom-sheet 用于底部弹窗内容，窄屏从底部展开，宽屏居中。简单输入和文字确认应直接使用 minibot-dialog。

自定义全屏弹层

页面自行绘制的全屏弹层，应在打开和关闭时成对调用 minibot.ui.setOverlay，由宿主在全局背景图上按矩形挖孔：

const rect = element.getBoundingClientRect();
await minibot.ui.setOverlay(true, {
  left: rect.left,
  top: rect.top,
  width: rect.width,
  height: rect.height,
  topRadius: 16,
  bottomRadius: 16,
  coversBottom: false
});

// 关闭时
await minibot.ui.setOverlay(false);

MiniBotBottomSheet、MiniBotDialog 打开时会自动上报弹层矩形并调用 setOverlay(true, rect)，关闭后恢复。页面自行绘制的弹层不应依赖这两个组件的行为。

插件事件

插件进程用 SDK 主动推送事件：

import { emit } from '@jieapi/plugin-sdk';

emit('records.changed', {count: 4});

页面侧：

const off = minibot.events.on((event) => {
  if (event.name === 'records.changed') {
    console.log(event.payload);
    refreshRecords();
  }
});
  • 事件仅发送给同一插件、当前已加载的页面；
  • 无页面时丢弃，不排队；
  • 不跨插件转发，也不会注入会话或触发新的 AI 推理；
  • 页面关闭或宿主销毁时应调用 off()。

适用于事件推送的场景：进程后台任务完成、定时器状态、浮层交互结果。

文件订阅

所有插件 HTML 页面均可订阅其读取的文件来源，无需增加运行时或声明 hook。订阅仅通知「数据可能发生变化」，由页面决定重读哪些内容；宿主不会重载 WebView。

const stopWatching = await minibot.fs.watch('data://records', {recursive: false}, (change) => {
  if (change.error) {
    console.error(change.error.code, change.error.message);
    return;
  }
  refreshRecords();
});

const stopLifecycle = minibot.events.on((event) => {
  if (event.name === 'ui.lifecycle' && event.payload.visible) {
    refreshRecords();
  }
});

await refreshRecords();

// 页面应用卸载时应清理；暂时退出页面时由宿主自动暂停监听。
await stopWatching();
stopLifecycle();

规则：

  • watch(path, options?, handler) 返回 Promise，解析为取消订阅函数；取消函数返回 Promise，可重复调用；
  • 也支持 watch(path, handler)；
  • 路径是当前执行环境的真实绝对路径，data:// 映射到插件自己的数据目录；本地模式为容器内路径，SSH 模式为远端路径；
  • recursive 默认为 false；未创建的路径按目录等待；如需监听尚未创建的文件，应订阅其父目录；
  • 回调收到 {subscriptionId, path, contextKey, changes: [{path, kind}], truncated}，kind 为 created、modified 或 deleted；
  • 路径始终按插件传入时的形式回传，不包含宿主私有目录；
  • 首次远端扫描成功时也会收到一次 changes: [] 的校准通知，不应仅在明细非空时刷新；
  • truncated 为 true 时应重新读取整个订阅范围；error 存在时表示订阅出现错误，不应据此清空已有数据；
  • 本地复用文件系统通知，默认约 300ms 合并一批，另有约 2 秒的文件快照检查兜底；
  • SSH 的工作区和配置目录使用约 2 秒的按需远端快照检查；同一远端工作区内的多个订阅共享工作区根的一次轮询，再按各自子路径过滤事件，以修改时间和大小判断变化；同一时间精度内、大小也相同的连续改写可能无法区分，重新显示页面时应再次校准；
  • 页面可见时监听，离开页面或 App 退到后台时暂停，回到页面时恢复；工作区、执行模式或 SSH 服务器变化时重建；
  • 每个页面最多 16 个订阅，应选择必要的小范围，避免递归监听整个工作区；
  • 文件订阅同样受范围限制：不能递归订阅整个文件系统、home 或 ~/.minibot 根，避免一次扫描整棵树。

文件订阅仅覆盖指定文件来源，不会自动推断数据库、HTTP API 或其他插件数据的变化。这类数据仍由插件进程通过 plugin.event 主动推送，或在页面显示时自行校准。

页面生命周期

ui.lifecycle 的 payload 为 {visible, reason, contextKey}，reason 为：

值 含义
shown 页面首次显示
resumed 从后台或隐藏状态回到前台
hidden 页面被隐藏或 App 退到后台
contextChanged 工作区、执行模式或 SSH 服务器变化

首次加载仍需主动获取数据；重新显示、回到前台和上下文切换用于校准缓存。不应仅依赖一次 Vue mounted。

运行事件

页面启动 AI 轮次后，会额外收到宿主的 chat.run.started 与 chat.run.finished 事件：

minibot.events.on((event) => {
  if (event.name === 'chat.run.finished') {
    console.log(event.payload.sessionId, event.payload.status, event.payload.error);
  }
});

status 为 running / success / error / cancelled；这些事件只说明轮次状态，正文仍通过 minibot.chat.listMessages 读取。

minibot.context() 返回当前 contextKey 和 visible。文件方法可在最后一个 options 参数中传入 {contextKey}；上下文已经变化时请求返回 STALE_CONTEXT，用于拦截仍在排队的旧项目操作。异步刷新结果仍应在页面侧核对上下文，正在编辑的输入不得被刷新直接覆盖。

let loading = false;

async function refreshRecords() {
  if (loading) return;
  loading = true;
  try {
    const ctx = await minibot.context();
    const result = await minibot.fs.read('data://records.json', {contextKey: ctx.contextKey});
    const current = await minibot.context();
    if (!current.visible || current.contextKey !== ctx.contextKey) return;
    render(JSON.parse(result.content));
  } catch (error) {
    if (error.code === 'STALE_CONTEXT') return;
    console.error(error.code, error.message);
  } finally {
    loading = false;
  }
}
