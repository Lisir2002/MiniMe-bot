# 10 域名绑定与 HTTPS

> 状态：服务器安装器已实现 `--domain`/`--access ip`、Caddy 配置和访问字段，但尚未用真实域名验证证书链路；App 当前骨架已支持 IP/域名可选地址、设备配对和创建基础云端容器，安装命令生成与完整七步向导尚未接入。

## 1. 目标

- 云端部署向导增加一个可选的“访问方式”步骤。
- 用户可以选择“先用 IP 测试”，也可以绑定自己的域名并自动启用 HTTPS。
- 域名是可选分支，不阻塞没有域名、暂时不想配置 DNS 的用户。
- 证书申请和续期全部在服务器完成，App 不接触域名服务商 API Token。
- 域名绑定失败时可以明确诊断，并回退到 IP 测试模式，不留下半配置状态。

非目标：

- 第一版不支持泛域名、通配符证书、多域名 SAN。
- 第一版不支持 Cloudflare、阿里云 DNS 等“一键解析”；用户手动添加 A/AAAA 记录。
- 第一版不做 App 内证书固定（certificate pinning），使用 Android 系统信任链。
- 第一版不把控制面直接暴露在公网 HTTPS 端口上；HTTPS 由反向代理终止。

## 2. 部署向导中的位置

原六步向导改为七步：

```text
1. 选择服务器
2. 访问方式（新增，可选）
3. 基础镜像
4. 初始化环境
5. 资源与策略
6. 确认
7. 部署进度
```

“访问方式”是独立一步而不是塞进“选择服务器”，原因：

- 用户需要在看到安装命令之前决定域名，安装参数只生成一次。
- 域名涉及 DNS 操作，需要独立说明和检测，不应和服务器选择混在一起。
- 独立步骤可以在“确认”页清楚展示最终访问地址和协议。

没有域名时，用户可以直接点“跳过，使用 IP 测试”，流程与现在一致。

## 3. 第二步：访问方式

### 3.1 页面结构

```text
第一步：连接控制面
服务器地址 [ 156.225.16.61:8787 或 https://example.com ]
[检测连接]

第二步：访问方式
○ IP + HTTP（测试）
○ 域名 + HTTPS（可选）
   当前地址：https://example.com
   需要服务器已完成域名解析和证书配置
[上一步]                       [配对并继续]
```

第一条地址可以是 IP，也可以是已经配好 HTTPS 的域名；第二步只展示识别出的访问方式，并允许返回修改。

### 3.2 默认与记忆

- 首次部署默认“先用 IP 测试”。
- 已经成功绑定过域名的服务器，再次部署时默认选中已保存的域名。
- 用户切换回 IP 测试时，必须显示明文 HTTP 风险提示；不默认替用户做降级。
- 域名输入不做自动补全，避免把用户输入发到第三方联想服务。

### 3.3 按钮行为

- “检测连接”：只请求 `/health`，不修改 DNS，也不发送设备 Token。
- 域名模式下，HTTPS 连接失败会同时提示检查 DNS 解析、80/443 端口和证书状态。
- “配对并继续”在地址格式非法或连接未通过时禁用；用户可以返回第一步改成 IP。
- IP 测试始终可选，不要求先有域名。

### 3.4 文案要点

- 域名连不上：`无法通过 HTTPS 连接域名，请检查 DNS 是否解析到这台服务器、80/443 是否可从公网访问，以及证书是否已签发。`
- 后续独立 DNS 预检再区分“未解析”“解析到错误 IP”“证书等待”，当前版本统一走 HTTPS 连接失败提示。
- IP 模式：`HTTP 会明文传输设备令牌和会话内容，只建议在测试阶段短时间使用。`

## 4. 域名校验规则

### 4.1 输入规范化

按顺序处理：

1. 去掉首尾空白。
2. 转小写。
3. 去掉开头的 `http://` 或 `https://`。
4. 去掉末尾的 `/` 和路径、查询参数。
5. 如果包含 `:` 端口，直接判为非法，第一版只允许 80/443 默认端口。
6. 如果包含 `@`、空格、下划线，判为非法。

只接受 ASCII 域名。第一版不接受中文域名和 punycode 输入，避免证书与 DNS 展示不一致。

### 4.2 格式规则

- 总长度不超过 253 字符。
- 至少两级，例如 `example.com`；`localhost` 这种单标签不接受。
- 每个标签 1–63 字符。
- 标签只能包含 `a-z`、`0-9`、`-`。
- 标签不能以 `-` 开头或结尾。
- 禁止 `*` 通配符。
- 禁止 IPv4/IPv6 字面量。
- 禁止 `example.com.` 这种结尾点（规范化时可直接去掉一个末尾点后再校验）。

实现时使用一个纯函数 `normalizeDomain(input): Result<String, DomainError>`，UI 和网络层共用，避免两套校验。

### 4.3 DNS 与域名连通性

第一版不单独做 A/AAAA 记录与服务器 IP 的比对，直接由 HTTPS 请求间接验证：

- 域名解析失败、证书未签发、80/443 不通，都会表现为 `https://domain/health` 连接失败。
- 失败提示统一列出三个排查方向：DNS、端口、证书，避免把 DNS 问题误报成 App 故障。
- 后续可补独立 DNS 预检，用系统解析结果与服务器公网 IP 比较，提前给出“指向错误”的提示。
- 不绕过证书错误，也不通过自建 DNS 规避系统解析。

### 4.4 HTTPS 检测

安装完成后请求：

```text
GET https://<domain>/health
```

判定：

- TLS 握手成功，证书由系统信任链验证通过。
- HTTP 状态码 200。
- 响应体包含控制面健康标识。
- 10 秒超时；最多轮询 3 分钟，间隔 5 秒，之后转为手动重试。

不做：

- 不忽略证书错误。
- 不信任自签名证书。
- 不把证书指纹作为第一版必经确认步骤。

## 5. 服务器安装器契约

### 5.1 命令行

在现有安装器上增加：

```bash
install.sh --binary <path> --domain example.com [--acme-email ops@example.com]
install.sh --binary <path> --access ip
```

规则：

- `--domain`：启用或更新域名模式；参数必须是已规范化的 FQDN，不带协议、端口、路径。
- `--acme-email`：可选，传给 ACME 账户注册；不填也能申请证书。
- `--access ip`：显式切换到 IP 测试模式。
- 三个参数都不传：保持已有访问方式；首次安装默认 IP 测试模式。
- `--domain` 与 `--access ip` 同时出现时直接报错，不做隐式优先级。
- 非法域名在安装任何组件之前失败，避免装到一半再回滚。

### 5.2 域名模式行为

安装器需要：

1. 将 `MINIBOT_HOST` 设为 `127.0.0.1`，控制面只监听本机。
2. 安装并启用 Caddy（固定版本或系统包，二选一，需在实施时锁定）。
3. 写入站点配置，反向代理到 `127.0.0.1:8787`。
4. 放行 80/443；不主动放开 8787。
5. 由 Caddy 自动申请和续期证书。
6. 将访问方式写入 `/etc/minibot/access.env`：

```text
MINIBOT_ACCESS_MODE=domain
MINIBOT_PUBLIC_URL=https://example.com
MINIBOT_DOMAIN=example.com
```

7. 如果 80/443 被其他程序占用，安装前失败并给出占用进程。
8. 重复执行 `--domain` 是幂等更新，不重复申请证书、不重建数据库。
9. 证书尚未签发时安装可以完成，状态标记为 `pending`，由 App 轮询；Caddy 会持续重试。

### 5.3 IP 测试模式行为

- `--access ip` 将 `MINIBOT_HOST` 设为 `0.0.0.0`，保留 8787 明文访问。
- 写入：

```text
MINIBOT_ACCESS_MODE=ip
MINIBOT_PUBLIC_URL=http://<服务器IP>:8787
```

- 如果之前配置过域名，需要移除 Caddy 站点并停止 Caddy，避免同一域名继续反代旧配置。
- 必须输出醒目警告：明文 HTTP 仅用于测试。

### 5.4 访问状态接口

`GET /api/v1/server/info` 增加只读字段：

```json
{
  "accessMode": "domain",
  "publicUrl": "https://example.com",
  "domain": "example.com"
}
```

- `accessMode`：`ip` / `domain`。
- 不返回证书私钥、ACME 账户信息、DNS Token。
- App 只信这个接口的地址展示，不自行拼接安装参数之外的 URL。

## 6. 失败处理与降级

| 场景 | App 表现 | 处理 |
| --- | --- | --- |
| 域名格式非法 | 输入框下方红色提示，“下一步”禁用 | 用户修改；不发起安装 |
| DNS 未解析 | 黄色警告，允许继续 | 提示添加 A/AAAA；安装后继续轮询 |
| DNS 指向其他 IP | 红色警告，允许继续 | 提示检查 CDN/代理和 A 记录 |
| 80/443 被占用 | 部署失败 | 展示占用进程，用户处理后重试 |
| 证书申请失败 | 部署进度显示“HTTPS 等待中” | 展示 Caddy 状态和常见原因；重试或改用 IP |
| HTTPS 健康检查失败 | 不标记部署成功 | 重试、复制诊断、改用 IP 测试 |
| 用户改用 IP | 重新执行 `--access ip` | 明确提示会关闭 HTTPS 并开放 8787 |
| 域名成功 | 显示 `https://domain` | 控制面保持 127.0.0.1，仅 Caddy 对外 |

降级原则：

- 不自动把用户从域名模式切到 IP 模式；必须用户点击确认。
- 降级时不删除数据、卷和容器，只改访问方式。
- 域名模式证书失败不能阻塞已经创建成功的容器；部署结果标记为“容器成功 / 访问待修复”。

## 7. 安全要求

- 域名模式控制面只监听 `127.0.0.1:8787`，公网只暴露 80/443。
- 反向代理必须保留原始 Host 和协议头，控制面按 HTTPS 生成外部链接。
- App 使用系统证书校验，不提供“忽略证书错误”开关。
- 不在 App 收集 DNS 服务商 Token；第一版只手动加解析记录。
- 安装日志和 App 诊断信息不得包含设备 Token、模型 Key、数据库密码。
- IP 明文模式必须显示风险，并在设置页持续标记“非安全连接”。

## 8. Phase 9 前置与 App 实施拆分

### 服务器侧（Phase 9 前置，先做）

- 安装器支持 `--domain`、`--acme-email`、`--access ip`。
- 域名规范化与校验函数（安装器与服务端共用规则）。
- Caddy 安装、站点配置、systemd、80/443 占用检查。
- `/etc/minibot/access.env` 写入与读取。
- `/api/v1/server/info` 增加访问方式字段。
- 幂等升级、回退 IP 模式、日志脱敏。

验收：

- `--domain` 安装后 `https://domain/health` 返回 200，证书链有效。
- 域名模式下 `ss -lntp` 看不到公网 8787。
- `--access ip` 能恢复 IP 测试，且不破坏数据库和容器。
- 重复执行安装不重复申请证书、不丢配置。
- 非法域名在安装前失败。

### App 侧（Phase 9）

- 七步向导增加“访问方式”页。
- `AccessMode`、`DomainBinding` 状态模型。
- 地址输入规范化、域名格式校验，HTTPS 连接间接验证 DNS 与证书。
- 安装命令带上 `--domain` 或 `--access ip`。
- 部署进度页轮询 `/health` 和 `/api/v1/server/info`，展示 HTTPS 状态。
- 失败诊断、重试、回退 IP 的确认弹窗。
- 域名成功后设置页展示 `https://domain`，IP 模式展示风险标记。

验收：

- 不填域名可完整走完部署，流程与旧版一致。
- 填合法域名且 DNS 正确时，部署完成后 App 自动切到 HTTPS 地址。
- DNS 未生效时能看到原因，不出现无限转圈。
- 证书失败时能一键回退 IP 测试，数据不丢。
- App 不保存任何 DNS 服务商 Token。
- 退出重进向导保留已填域名和访问方式选择。

## 9. 测试用例

域名校验：

- `example.com` 通过。
- `HTTPS://Example.COM/` 规范化为 `example.com` 通过。
- `example.com:443`、`https://example.com/path`、`*.example.com`、`localhost`、`1.2.3.4` 拒绝。
- 64 字符标签、254 字符总长拒绝。

安装器：

- 首次 `--domain` 安装成功，Caddy active，控制面 loopback。
- 重复 `--domain` 不重复签发。
- 已有域名后 `--access ip` 回退，8787 可从测试来源访问，Caddy 站点移除。
- 80/443 被 nginx 占用时安装前失败。
- 非法域名不产生任何 systemd/Caddy 残留。

App：

- DNS 记录匹配、缺失、指向错误三种状态展示正确。
- 安装后证书 pending → ready 的状态切换。
- 杀掉 App 重开，向导恢复到“部署进度”且域名不丢。
- 回退 IP 后地址、警告和后续部署参数一致。
